## Spec Kit 專案更新

### 版本總覽

**v0.8.4–v0.8.7**（5 月 1–7 日）以四個修補版本揭開本月序幕，交付了今年最受期待的功能：**多個 AI 代理整合並存的多重安裝支援**（#2389），讓單一專案能同時啟用多個代理。這關閉了五個存在長達 228 天的長期 issue。這些版本也新增了 **`/speckit.implement` 中的憲章治理**（#2460），確保實作階段現在會載入 `constitution.md`，在產生程式碼時強制執行治理。**驗證提供者註冊表**（#2393）新增了以設定驅動的多平台驗證。**Lingma 代理**加入整合陣容。安全性強化包括將所有其餘 GitHub Actions 釘選至不可變的 SHA（#2441），以及用於避免 SSRF 類錯誤的 URL 格式驗證（#2449）。七個新的社群擴充功能與六個治理主題的新預設集也隨之登場。 [\[github.com\]](https://github.com/github/spec-kit/releases)

**v0.8.8–v0.8.10**（5 月 8–14 日）發佈了三個聚焦穩定性的版本。**版本功能回報**（#2548）改善了升級可見性。錯誤修復處理了 Kiro CLI 的 `$ARGUMENTS` 佔位符（#1926，開放 52 天）、對 markdownlint 安全的範本中繼資料（#1343，開放 147 天），以及預設集技能說明的優先順序。`__init__.py` 拆解系列以 PR 1–2／8 展開，抽出 `_console.py`、`_assets.py` 與 `_utils.py`。七個新擴充功能加入（Architecture Workflow、Agent Governance、BrownKit、Schedule、Reqnroll BDD、MDE、Changelog），以及兩個新預設集（MDE、game-narrative-writing）。文件網站迎來大規模翻修：首頁改版為四支柱卡片版面、安裝章節予以簡化，社群擴充功能表格移至文件網站。 [\[github.com\]](https://github.com/github/spec-kit/releases)

**v0.8.11–v0.8.13**（5 月 15–21 日）交付了三個版本，儲存庫也**突破 100K 顆星**。**代理式型錄投稿**（#2655）為社群型錄貢獻新增了 AI 輔助工作流程。一套**高保證規格工作流程**完成文件化（#2518）。while／do-while 迴圈的過時輸出錯誤（#2592）在當天被發現並修復。**整合自動模式**（#2421）現在會跟隨專案已初始化的 AI，而非寫死 Copilot。PowerShell UTF-8 BOM 問題（#2280）獲得解決。四個新擴充功能加入（Team Assign、Interactive HTML Preview、Time Machine、Superpowers Implementation Bridge），使型錄達到 **103 個條目**——突破 100 大關。 [\[github.com\]](https://github.com/github/spec-kit/releases)

**v0.8.14–v0.8.17**（5 月 22–28 日）以四個版本為本月收尾。**Hermes Agent** 成為新的整合目標（#2651）。工作流程獲得了 **`{{ context.run_id }}` 範本變數**（#2664）。新的 `SPECKIT_INTEGRATION_<KEY>_EXTRA_ARGS` 環境變數（#2596）讓使用者能向代理子行程傳入額外旗標。**從 URL 安裝擴充功能現在會要求確認**（#2745），是 URL 式安裝的安全性改善。規格品質檢核清單現在會在 **clarify 更新規格後重新驗證**（#2715）。Token Budget、Product Spec 與 Workflow Preset 擴充功能加入型錄，總數達到 **105 個條目**。 [\[github.com\]](https://github.com/github/spec-kit/releases)

### 架構與重構

5 月最重大的內部工作是 **`__init__.py` 拆解系列**，已推進至 8 個 PR 中的第 1–4 個。這次系統性的抽取將 `_console.py`、`_assets.py`、`_utils.py`、`_version.py` 與 `commands/` 套件移出單體的 init 模組，改善了可維護性與貢獻者入門體驗。**ExtensionCatalog 遷移至共用型錄堆疊基礎**（#2437），減少了擴充功能、預設集與整合型錄之間重複的型錄處理。 [\[github.com\]](https://github.com/github/spec-kit/releases)

### 錯誤修復與安全性

十四個版本帶來了強勁的修復節奏。解決的長期 issue 包括 Kiro CLI 的 `$ARGUMENTS` 佔位符（52 天）、markdownlint 範本中繼資料換行（147 天），以及新增代理命令的 `--ai` 旗標（136 天）。PowerShell UTF-8 BOM 問題已修復，預設集技能算繪現在能正確解析 `__SPECKIT_COMMAND_*__` 參考（#2717），Windows 關卡步驟當機也獲得處理（#2635）。

安全性改善包括 **URL 式擴充功能安裝確認**（#2745）、**將 GitHub Actions 釘選至不可變 SHA**（#2441）、**URL 格式驗證**（#2449），以及將社群投稿工作流程限制為僅標籤事件（#2741）。 [\[github.com\]](https://github.com/github/spec-kit/releases)

### 擴充功能與預設集生態系

社群擴充型錄在 5 月從 92 個成長至 **105 個條目**，於 5 月 21 日突破 **100 大關**。本月新增了十三個擴充功能。社群預設集從 18 個成長至 **21 個條目**，新增三個預設集。

依類別值得注意的新擴充功能：

- **架構與治理**：Architecture Workflow（bigsmartben）、Agent Governance（bigben）、Architecture Guard（DyanGalih）、BrownKit（Maksim Shautsou）
- **成本與 token 管理**：Cost Tracker（Quratulain-bilal）、Token Analyzer（Chris Roberts）、Token Budget（Tine Kondo）
- **代理編排**：Agent Orchestrator（pragya247）、Multi-Model Review（formin）
- **專案管理**：Team Assign（tarunkumarbhati）、Changelog（Quratulain-bilal）
- **雲端與企業**：供 Azure 使用的 Spec2Cloud（Azure Samples）、.NET Framework 至現代 .NET 遷移（RogerBestMsft）
- **API 與生命週期**：API Evolve（Quratulain-bilal）、Product Spec（spec-kit-product 貢獻者）
- **品質**：附 CP-SAT 求解器的 Schedule（Julio César Franco Ardila）、Reqnroll BDD（LoogaCY Studio）、MDE（AI-MDE）
- **規格探索**：Interactive HTML Preview（bigsmartben）、Time Machine（te3yo）
- **跨工具橋接**：Superpowers Implementation Bridge（lihan3238）

新的治理主題預設集占主導地位：a11y-governance、architecture-governance、security-governance、cross-platform-governance、agent-parity-governance，以及 Spec2Cloud 預設集。創意預設集包括 game-narrative-writing 與 MDE。

擴充生態系也透過積極維護展現成熟。**Architecture Guard** 歷經四個版本（v1.6.7 → v1.8.9），新增文件品質改善與治理功能。**Memory MD** 發佈多次更新（v0.6.9 → v0.8.0），新增 `speckit.memory-md.log-finding` 命令。**Security Review** 達到 v1.4.5，新增 `speckit.security-review.log-finding` 命令。**Superpowers Implementation Bridge** 快速演進（v0.5.0 → v0.7.0）。**Squad Bridge** 更新至 v1.3.0、**Fiction Book Writing** 至 v1.8.1、**Security Governance** 至 v0.4.0、**MemoryLint** 至 v1.4.0。 [\[github.com\]](https://github.github.io/spec-kit/community/extensions.html)

## SDD 生態系與產業趨勢

### 分析師觀點

The Futurum Group 的 **Mitch Ashley** 在 DevOps.com 提出了迄今最重大的 SDD 分析師框架：「GitHub 的 Spec Kit 顯示，AI 輔助寫程式正從提示詞轉向持久、具版本的規格。各家廠商正競相擁有那份治理意圖的產物，橫跨 Copilot、Claude Code 與 Gemini CLI。」他警告「每個檢查點的驗證都不能延後交給產出它的代理」——呼應了專案本身對各階段邊界人工監督的強調。 [\[devops.com\]](https://devops.com/githubs-spec-kit-puts-the-spec-back-in-software-development/)

### 生產實務手冊模式

**Truong Phung** 的 61 分鐘生產實務手冊，代表社群內容深度的新層次。Phung 不是把 Spec Kit 當成工具來評測，而是將 SDD 視為理所當然，圍繞 **Spec → Plan → Code → Verify 迴圈**打造完整指南，並以 Spec Kit 與 Superpowers 為參考實作。他開頭的七個真理——「瓶頸從打字轉移到了思考」、「上下文工程 > 提示詞工程」，以及「PR 是工作單位，而非工單」——掌握了圍繞結構化 AI 開發新興的實務者共識。 [\[dev.to\]](https://dev.to/truongpx396/building-production-grade-fullstack-products-with-ai-coding-agents-a-practical-playbook-2idd)

### 競爭格局

**MarkTechPost 對九種 SDD 工具的比較**稱 Spec Kit 為「社群採用度最高的開源選項」，同時將競爭者定位在不同軸線上：**Kiro**（整合式 IDE，具備 EARS 式規格與代理 hook）、**BMAD-METHOD**（約 48K 顆星、12 個以上專門代理）、**GSD**（約 64K 顆星、精簡的 meta-prompting）、**Augment Code**（供 400K 以上檔案使用的上下文引擎，並非規格撰寫工具）、**OpenSpec**（約 52K 顆星、變更課責與稽核軌跡），以及 **Tessl**（規格註冊表，含 10K 以上的函式庫規格）。 [\[marktechpost.com\]](https://www.marktechpost.com/2026/05/08/9-best-ai-tools-for-spec-driven-development-in-2026-kiro-bmad-gsd-and-more-compare/)

以月底的 107K 顆星，Spec Kit 是 **GitHub 星數前 100 名儲存庫中唯一的規格驅動開發工具**——上述競爭者無一接近 100K 門檻。更廣的前 100 名清單包括與 AI 相鄰的專案，如代理技能框架（obra/superpowers 有 212K、anthropics/skills 有 143K）、代理 harness 工具與 LLM 推論引擎，但 Spec Kit 是唯一圍繞規格優先開發工作流程打造的工具。 [\[github.com\]](https://github.com/search?q=stars%3A%3E100000&type=repositories&s=stars&o=desc)

## 藍圖

未來開發中正在討論或進行中的領域：

- **CLI 架構清理**——`__init__.py` 拆解（已完成 4／8）持續朝模組化命令結構推進。這項內部清理改善了貢獻者入門與測試隔離。 [\[github.com\]](https://github.com/github/spec-kit/releases)
- **規格生命週期管理**——規格漂移與上下文腐蝕仍是各篇文章中最常被提及的疑慮（DevOps.com、DeployHQ、テックオーシャン）。clarify 重新驗證（#2715）與 reconcile 擴充功能是漸進的步伐；更完整的解法值得期待。 [\[devops.com\]](https://devops.com/githubs-spec-kit-puts-the-spec-back-in-software-development/)
- **多代理工作流程**——多重安裝支援（#2389）是最受期待的功能。下一個前沿是跨階段編排多個代理，這種模式社群的 MAQA、Fleet 與 Conduct 擴充功能已經在探索。 [\[github.com\]](https://github.com/github/spec-kit/releases)
- **型錄成熟度**——型錄探索 CLI（v0.8.3）、代理式投稿（v0.8.13）與 GITHUB_TOKEN 驗證（v0.8.2）正朝套件管理員體驗邁進。隨著型錄突破 100 個條目，策劃與品質訊號變得至關重要。 [\[github.com\]](https://github.com/github/spec-kit/releases)
- **體驗簡化**——部署缺口（DeployHQ）、小任務的儀式開銷（テックオーシャン、spec-coding.dev）與冗長輸出（Thoughtworks Radar）仍是未解疑慮。精簡預設集、TinySpec 擴充功能與工作流程引擎提供了答案；這些選項的可發現性仍是機會所在。 [\[deployhq.com\]](https://www.deployhq.com/blog/spec-kit-copilot-workspaces-deployment)
- **邁向穩定版本**——一個月十四個版本，反映了 1.0 之前的動能。git 擴充功能預設關閉通知（#2432，於 v0.10.0 設關卡）與 `--no-git` 棄用（於 v0.10.0 移除），都指向 API 穩定的路徑。 [\[github.com\]](https://github.com/github/spec-kit/releases)
