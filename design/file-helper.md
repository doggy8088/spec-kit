# 限定範圍的 FileHelper 與專案政策

`specify_cli.file_helper.FileHelper` 負責在單一明確建立的根目錄下執行檔案系統操作。專案命令邊界現在會驗證已保存的政策，而初始化選項的啟動 I/O 則使用此輔助工具。其他既有的命令檔案系統操作**尚未移轉**：僅載入政策並不會對這些操作強制執行符號連結行為。共用基礎設施、註冊、受管儲存、型錄、指令碼與執行階段操作，在其相依的移轉階段完成前，仍維持既有行為。

只有 `specify init --allow-symlinks` 會公開此設定；初始化預設為拒絕，並將字面 JSON 布林值 `allow_symlinks` 保存於 `.specify/init-options.json`。未帶該旗標重新初始化時，記錄為 `false`。其他專案範圍的命令在每次呼叫時都會驗證所選專案目前的設定，包括同一行程中的連續呼叫。不使用全域旗標、逐命令覆寫、可變的全域政策或快取。無專案的說明／版本／工具操作不需要設定。`check` 是選擇性的專案消費者：它會在所選 cwd／覆寫邊界驗證任何現有政策，再載入已安裝的整合或檢查工具，但仍允許 cwd 中缺少專案標記或設定。既有的解析規則，包括 `SPECIFY_INIT_DIR`、套件組祖先搜尋、直接工作流程檔案根目錄與明確的初始化目標，決定要檢查哪個根目錄；政策載入不會新增祖先探索。事件執行維持其僅以 cwd 選擇的行為，不取得覆寫或專案標記要求；它會在呼叫處理常式前，預先檢查任何現有的 cwd 政策。套件組祖先搜尋僅在標記確實不存在時才繼續。較近的禁止／現有無效 `.specify` 項目會在該候選位置失敗，而不是選擇祖先或在其他位置初始化。

缺少設定或缺少鍵表示拒絕。只有字面 JSON `true`／`false` 值有效。無效的 JSON、非物件文件、無效編碼、無法讀取的檔案與無效值，都會在專案邊界、變更前明確失敗。懸空的設定連結屬於現有的禁止項目，而非缺少的預設值。

設定啟動的讀取**與寫入**一律使用拒絕模式的輔助工具，即使已保存的操作政策或初始化旗標允許符號連結亦然。在受信任的專案根目錄之下，`.specify` 與 `init-options.json` 不得是連結或不支援的重解析點。根目錄／作業系統別名保留基礎所定的受信任邊界處理。對於新的初始化根目錄，`prepare_init_root` 使用以最近的現有父目錄為根的拒絕模式輔助工具，建立其缺少的後綴；現有且明確提供的根目錄別名受信任。`preflight_init_root` 驗證原始請求的拼寫而不建立根目錄，包括正規化前缺少父目錄的遍歷與懸空父目錄證據。在存在性探測之前，`..` 之前的每個前綴都必須是現有目錄：否則 Windows 可能把 `missing/../existing` 摺疊成看似存在的目標。有效的現有目錄／根目錄別名遍歷仍受信任；前綴權限與其他 I/O 失敗仍為明確錯誤。初始化的外部配接器生命週期會在讀取整合記錄、載入配接器或準備型錄套件之前，驗證現有目標政策。當該生命週期需要交易時，它會在既有鎖定下、使用原始請求的拼寫與 `prepare_init_root` 建立目標，再呼叫內層處理常式。記錄的交易前目錄狀態保留該拼寫，因此新建的根目錄不會變成虛假的現有目錄衝突。鎖定、日誌與處理常式操作在原始拼寫驗證後，保留其正規專案身分。

## 供相依移轉使用的政策交接

`specify_cli._file_policy.read_project_options(root)` 是嚴格的啟動讀取器；它與舊版寬容的 `load_init_options` 程式庫 API 分開。`project_files(root)` 會重新讀取政策，並回傳不可變的 `FileHelper(root, allow_symlinks=...)`。請將該回傳的操作擁有者明確傳給領域消費者；不要重建預設輔助工具而遺失政策。`specify_cli._project.resolve_specify_project_files()` 執行一般的現有專案解析，並為新的 CLI 配接器回傳相同的交接。使用其他既定根目錄的命令，則對其實際選擇的根目錄呼叫 `project_files`。輔助工具只保留給目前操作使用；後續呼叫會解析出新的輔助工具，因此手動編輯會生效。請將回傳的擁有者用作內容管理器，或在其擁有者的清理路徑中呼叫 `close()`，以在該操作邊界釋放保留的根目錄控制代碼。

`specify_cli.integration_state` 輔助工具是此交接的明確受管中繼資料例外。它們對 `.specify/integration.json` 的讀寫一律使用拒絕模式，包括 `allow_symlinks` 為 true 時的受含連結。這保留了[整合生命週期對符號連結寫入目的地的限制](integration.md#儲存載入與生命週期)，在快照與變更之前即加以防範。此保證不涵蓋未移轉的消費者，例如 `bundles.project.active_integration`，其經包含檢查的讀取仍可跟隨受含的狀態檔案連結。

既有的回傳 Path 解析器會預先檢查政策，而不改變其回傳型別或領域建構函式。它們不會隱含地為未移轉的領域消費者配備操作輔助工具。失敗會轉譯為既有的命令診斷，JSON 政策失敗時在 stderr 輸出單一 `{"error": "..."}` 且 stdout 為空；構件／列表介面保留其錯誤封裝合約。構件列表／資訊會在其共用應用操作中驗證其明確的專案根目錄，因此 CLI 與 MCP 對等配接器共用相同的政策語意，同時保留各自的錯誤封裝。

`save_project_options` 與相容的 `save_init_options` 寫入器使用拒絕模式的啟動 I/O。初始化會將其擁有的設定合併到現有有效選項中，保留不相關的欄位。整合選項的更新／清除／版本路徑使用嚴格讀取器並保留 `allow_symlinks`。未移轉的寬容程式庫讀取器保留其既有的缺少／格式錯誤回退合約。設定寫入器會在現有檔案變更觀察者拍攝快照前，驗證其拒絕模式目的地，然後在寫入前後保留觀察者掛鉤。因此，下游初始化失敗仍由既有生命週期回滾涵蓋，包括先前的政策與不相關選項。

```python
from specify_cli.file_helper import FileHelper

with FileHelper(project_root) as files:  # 預設拒絕符號連結
    files.mkdir("generated", exist_ok=True)
    files.create_text("generated/config.txt", "initial\n")
    files.write_text("generated/config.txt", "updated\n")
    content = files.read_text("generated/config.txt")
    files.delete("generated", recursive=True)
```

## 邊界與政策

每個輔助工具都有凍結的根目錄與 `allow_symlinks` 設定。相對操作路徑以根目錄為基準。絕對路徑必須位於所提供根目錄或其正規等價路徑之下。包含 `..` 的使用者操作路徑，會在其根目錄相對後綴中被拒絕，而不是在檢查前先正規化。呼叫端建立的根目錄拼寫本身可包含 `..`；支援由該確切提供的根目錄前綴衍生的絕對操作路徑。只有該受信任前綴會在檢查操作元件前被移除，不會對根目錄做詞彙摺疊，也不會忽略其餘後綴中的遍歷。連結目標可包含 `..`，但會逐元件走訪，且不得離開根目錄，即使暫時也不行。Windows 的有根但非絕對路徑（`/outside/file`、`\outside\file`）與磁碟相對路徑（`C:outside/file`、`C:`），無論是操作路徑還是連結目標，一律拒絕。它們不是根目錄相對路徑：聯結它們可能重設根目錄或磁碟。完全絕對路徑仍需符合限定範圍的根目錄比對。對於 Windows 包含比較，擴充長度的磁碟與 UNC 拼寫（`\\?\D:\project\file`、`\\?\UNC\server\share\project\file`）會在目標端與根目錄端都與其一般等價形式比較。這不會解析連結或摺疊 `..`：存取階層的證據會保留供元件走訪使用。UNC 命名空間標記以不區分大小寫方式比對，其餘路徑的原始拼寫則予以保留。外部目標、含糊的有根相對路徑與不支援的裝置命名空間仍被拒絕。POSIX 檔案名稱不會被重新詮釋為 Windows 路徑拼寫。

呼叫端必須建立受信任且現有的目錄根。其別名只解析一次，包括作業系統與工作樹別名；根目錄本身與其上方的作業系統祖先不受遍歷政策約束。因此，即使在拒絕模式下，明確將連結目錄建立為根目錄，也表示信任該別名。該邊界*之下*的連結，會同時在原始存取路徑與任何跟隨的目標階層中檢查。無關的專案符號連結不會阻止操作。輔助工具無法跨到另一個根目錄；呼叫端需為獨立的專案／來源／受管邊界建立各自的輔助工具。

在支援的刪除後端上，建構會保留正規根目錄的控制代碼，直到 `close()` 或內容管理器結束。讓原始目錄保持開啟，可防止其身分在輔助工具存續期間被另一個目錄重複使用；僅憑儲存的裝置／inode 編號並非繫結依據。在 POSIX 上，該控制代碼在可用時使用僅搜尋存取。在 Windows 上，建構僅要求根目錄中繼資料存取（`FILE_READ_ATTRIBUTES`）並允許刪除共用；它不會要求正規祖先的目錄列舉存取。保留的參照會從該控制代碼選取帶標籤的身分識別方案。優先使用完整的 128 位元 `FileIdInfo` 身分識別。若該查詢回報 `ERROR_INVALID_FUNCTION`、`ERROR_NOT_SUPPORTED` 或 `ERROR_INVALID_PARAMETER`，或回傳全零 ID，輔助工具會查詢已開啟磁碟區的檔案系統，並僅對 FAT、FAT32、exFAT 或 NTFS，使用 `GetFileInformationByHandle` 的磁碟區序號加上非零 64 位元檔案索引。磁碟區查詢與控制代碼相關，透過檔案系統驅動程式運作，而非以路徑為基礎的磁碟區查找，包括網路驅動程式提供必要資訊的情況。ReFS 與無法識別的檔案系統，不會回退到可能含糊的 64 位元索引。存取遭拒、共用與其他不相關的錯誤仍會傳播，而不會選取較弱的身分識別。
在接受之前，建構會將從取得的控制代碼獲得的 Python 原生中繼資料，與最初觀察到的根目錄中繼資料比較。此比較不會重新開啟根目錄路徑，因此取代後再還原，無法替換成不同的保留物件。中繼資料查詢使用暫時的不可繼承複本，並讓原始參照保持開啟。
若該參照或身分識別查詢不可用，原生功能錯誤會延後到 `delete()` 才提出，而不會阻擋一般的讀寫操作。快取的錯誤不保留追蹤記錄；每次失敗的刪除都會提出獨立的淺層複本，保留原生錯誤型別與檔案系統細節。

Windows 刪除會另外在不允許刪除共用的情況下，透過磁碟／共用根目錄固定正規祖先階層，再使用已選取的方案，查詢該根目錄控制代碼與保留的參照。它比較的是即時身分識別，而非快取的舊版索引：FAT ID 在重新命名後可能變更。它既不會在操作中途重新協商身分識別方案，也不會比較來自不同方案的身分識別。這些操作階段控制代碼在每個正規祖先（包括輔助工具根目錄之上的祖先）上，都要求 `FILE_LIST_DIRECTORY` 與 `FILE_READ_ATTRIBUTES`，並拒絕重解析點。因此，允許遍歷但不允許列舉的 ACL 可能阻擋刪除，同時仍允許啟動讀取。Windows 刪除也會在連結解析全程保留所存取父目錄的非重解析控制代碼，然後才分類子項目或讀取連結目標。每個子項會相對於其原生父控制代碼開啟，而不是重建絕對路徑。從已開啟的葉控制代碼讀取中繼資料與符號連結目標；目錄名稱則從目錄控制代碼列舉。相對的原生開啟會同時要求 `FILE_SYNCHRONOUS_IO_NONALERT` 與 `SYNCHRONIZE`，包括目錄在內，因此列舉不會在待處理的目錄查詢完成前耗用緩衝區。這些存取的目錄也要求目錄列舉／讀取屬性存取。解析控制代碼在選取後釋放；原生變更父目錄與根目錄祖先階層則在預檢與移除期間保持保留。僅憑目錄共用鎖定，無法防止就地重解析變更：與控制代碼相關的操作會保留已開啟的目錄物件，而不是跟隨其變更後的路徑。這些鎖定在刪除結束時釋放；僅中繼資料的參照則保留到輔助工具關閉為止。自動終結只是相容性備援，不能取代確定性的清理。啟動設定與受管整合狀態消費者會明確關閉各自的輔助工具。已安裝工作流程列表也會在每次驗證、註冊表讀取與成功結束時，關閉其 `project_files()` 擁有者；其他接收 `project_files()` 的消費者擁有其生命週期。固定根目錄不會讓其他以路徑為基礎的操作變成與描述元相關，也不會改變其已記錄的並行限制。

| 操作 | 預設拒絕 | 明確允許 |
|---|---|---|
| 讀取檔案 | 拒絕存取的父層或葉節點連結 | 僅跟隨現有且受含的一般檔案目標 |
| 建立目錄 | 在建立父層前拒絕存取的連結 | 跟隨受含的目錄連結；拒絕懸空目標 |
| 獨占建立檔案 | 拒絕存取的連結 | 跟隨受含的父層；拒絕現有葉節點而不開啟其目標 |
| 原子寫入／upsert | 拒絕存取的連結 | 取代已解析的一般檔案目標並保留每個連結 |
| 非原子文字覆寫／upsert | 拒絕存取的連結 | 就地更新已解析的一般檔案目標，並保留每個連結 |
| 刪除葉節點連結 | 拒絕且不變更 | 取消連結，包括懸空、循環或外部目標連結 |
| 透過連結父層刪除 | 拒絕且不變更 | 刪除受含的目標項目，父層連結保持完整 |
| 遞迴刪除 | 預檢所有子孫並在變更前拒絕任何連結 | 預檢所有子孫；取消連結而不遍歷其目標 |
| 建立符號連結 | 拒絕 | 要求現有且受含的檔案／目錄目標 |

## API 與失敗

- `close()` 會釋放輔助工具保留的根目錄控制代碼，且可重複呼叫。`with FileHelper(...) as files:` 在成功與失敗時都會關閉。對已明確關閉的輔助工具執行操作，會提出 `FileHelperError`。
- `mkdir(path, parents=False, exist_ok=False)` 會建立目錄。
- `read_bytes(path)`／`read_text(path, encoding="utf-8")` 會讀取一般檔案。
- `create_bytes(path, content, mode=0o644)`／`create_text(...)` 會以獨占方式建立具有現有父目錄的檔案。不跟隨的 `lstat` 預檢會在開啟目的地之前，拒絕既有的葉節點，包括懸空連結。如此可避免在即使有獨占開啟旗標仍會跟隨懸空連結的後端上建立目標。`O_EXCL` 與 `O_NOFOLLOW`（如可用）仍會使用；政策解析出的父目錄階層會在建立過程中錨定。POSIX 會開啟每個已解析的目錄而不跟隨連結，並相對於最終的目錄描述元建立葉節點。僅搜尋控制代碼（`O_PATH` 或 `O_SEARCH`，如可用）可避免增加目錄讀取權限要求；當較舊的 Python 組建未公開該常數時，macOS 會使用原生的 `O_SEARCH` 值。走訪會在開啟子目錄後關閉前一個父目錄，讓作用中目錄描述元的數量與路徑深度無關。
  Windows 會以不允許刪除共用的非重解析控制代碼，固定正規根目錄與每個已解析的父目錄。每個錨定的目錄都必須允許 `FILE_LIST_DIRECTORY` 與 `FILE_READ_ATTRIBUTES` 存取。因此，允許建立檔案但拒絕目錄列舉的 ACL，可能導致建立在開啟葉節點前就失敗。
  允許的受含父層連結與受信任的根目錄別名會在錨定前解析；它們並未被禁止。父目錄必須已存在，且提供的模式仍受行程 umask 篩選。不支援的錨定原語會明確失敗，而不會回退到未錨定的建立。
- `write_bytes(path, content, mode=0o644)`／`write_text(...)` 會以原子方式建立或更新具有現有父目錄的檔案。文字變體也接受 `encoding="utf-8"`。取代檔案使用提供的模式；中繼資料與硬連結身分識別不會保留。原子是指同一目錄內的 `os.replace`，而非當機耐久性。
- `overwrite_text(path, content, encoding="utf-8")` 是具現有父目錄的**非原子文字 upsert**，用於設定相容性。它使用與其他操作相同的存取路徑／連結／包含檢查，僅跟隨允許的既有受含檔案目標，並保留連結鏈與目標 inode（包括硬連結身分識別與權限）。新檔案使用經行程 umask 篩選的 `0o666`；文字編碼與原生換行轉換與先前的設定寫入器相符。編碼或 I/O 失敗會傳播，寫入失敗可能留下截斷／部分內容。這不是硬連結侷限：硬連結別名仍可觀察到更新。
  在政策解析後，POSIX 會相對於已開啟的父描述元，以不跟隨旗標開啟每個已解析的目錄，在支援時使用搜尋／僅路徑存取，讓無法讀取但可搜尋的父目錄仍可使用，並在開啟子目錄後關閉前一個目錄。描述元用量維持與路徑深度無關的有界數量。接著會開啟葉節點而不截斷。Windows 會以不允許刪除共用的非重解析控制代碼，固定正規根目錄與每個已解析的父目錄。每個錨定的目錄都必須允許 `FILE_LIST_DIRECTORY` 與 `FILE_READ_ATTRIBUTES` 存取。因此，允許寫入檔案但拒絕目錄列舉的 ACL，可能導致覆寫在開啟葉節點前就失敗。既有的非重解析葉節點會在不截斷的情況下開啟。對於缺少的葉節點，在獨立擁有的執行期暫存目錄中，以 CRT 建立的空隨機名稱探測，會在不變更行程遮罩的情況下，擷取經遮罩的建立屬性。此暫存根目錄會另外固定、不含專案資料，並在原生不跟隨獨占建立目的地之前移除。專案中不會建立可拋棄的同層檔案，因此目的地建立不需要專案刪除權限。執行期暫存儲存失敗仍是明確的錯誤。
  在這些呼叫之間引入的葉節點，會導致明確的建立錯誤。已開啟的葉節點會在文字 I/O 全程保持持有。兩種路徑都會在截斷同一個描述元之前，檢查已開啟的檔案型別。在 POSIX 上，交換父目錄無法透過新連結重新導向建立或截斷。允許的連結仍由一般的政策走訪解析；錨定走訪會對其已解析的目標操作，而非原始連結拼寫。
  Windows 建立也會遵循 CRT 行程遮罩：遮罩擁有者寫入位元會建立唯讀檔案，與原生文字建立相符，且不變更既有檔案的屬性。
- `delete(path, recursive=False)` 會取消連結檔案／連結，或移除目錄。非遞迴的目錄刪除要求目錄為空。已建立的根目錄無法刪除。遞迴列舉與每次移除都使用錨定的目錄。每次刪除都會借用建構時保留的根目錄控制代碼、檢查目前命名的根目錄是否被取代，並在預檢與所有移除過程中使用該原始錨點。POSIX 會將此保留的根目錄用於元件分類、連結目標讀取與解析、遞迴預檢與逐項重新驗證，以及與描述元相關的列舉與 `unlink`／`rmdir`。正規路徑名稱用於識別根目錄相對項目，但不會為中繼資料或連結解析重新開啟。Windows 會在根目錄取得期間驗證完整的正規祖先階層，再於子項開啟、中繼資料查詢、連結目標讀取與列舉過程中，攜帶原生目錄控制代碼。
  移除會以 `DELETE` 存取開啟葉節點本身，並以 `FileDispositionInfo` 標記同一個控制代碼；它不會呼叫以路徑為基礎的 `unlink` 或 `rmdir`。這不會改變在根目錄建立時解析出的別名的受信任處理。允許的受含父層連結會在保留的邊界內解析，葉節點連結仍會取消連結而非跟隨。缺少必要目錄描述元操作的平台會以 `ENOTSUP` 失敗，而非以僅路徑刪除。
  POSIX 走訪與移除會在可用時使用搜尋／僅路徑描述元（`O_SEARCH` 或 `O_PATH`），包括在未公開該常數的 Python 組建上使用 Darwin 原生的 `O_SEARCH` 值，因此僅寫入與執行父目錄中的已知項目仍可移除。只有正在列舉的目錄才要求具讀取能力的描述元；沒有搜尋／僅路徑旗標的系統則保留具讀取能力的走訪。遞迴列舉仍要求目錄讀取權限，移除仍要求作業系統一般的目錄權限。
  預檢會相對於其錨定的父目錄，直接以可讀方式開啟列舉的子項，不先做僅搜尋開啟或 `"."` 重新開啟。因此，空的可讀目錄不需要自身的搜尋權限即可移除；存取非空目錄中的子項仍要求搜尋權限。父目錄仍需要移除其目錄項目所需的權限。
  在使用具讀取能力備援的系統上，根目錄建立也要求根目錄的讀取權限。
  POSIX 元件解析與最終父目錄錨定只保留目前的走訪描述元，在釋放前一個描述元之前開啟其子項。其作用中描述元數量維持與操作路徑深度無關的有界數量，此外還有輔助工具保留的根目錄。連結目標跳轉與 `..` 會透過該根目錄重新錨定，而不是在重新命名後跟隨已開啟目錄的實體父目錄。Windows 會為其與子項相關的走訪保留原生目錄控制代碼，包括遞迴預檢與移除期間。
  POSIX 遞迴預檢與變更使用明確的工作清單與兩個獨立的八目錄控制代碼快取。所選的父目錄與已建立的根目錄維持錨定在這些快取之外。未快取的父目錄會以不跟隨旗標，從最近的保留前綴逐元件重新取得，並在快取填滿時釋放最近最少使用的控制代碼。已移除的目錄會被逐出，預檢控制代碼不會重用於變更。作用中描述元維持與遞迴深度無關的有界數量，包括暫時開啟與列舉；工作清單與完整計畫的記憶體仍隨所選樹狀結構擴展。
  重新取得被逐出的前綴，會以額外的開啟次數換取固定的控制代碼預算。開啟總數可能隨造訪路徑長度的總和增長，而非無條件與目錄數量成線性關係。Windows 會保留其原生控制代碼走訪，而不逐出子項相關操作所需的控制代碼。完整計畫在任何移除前仍會先預檢。
- `symlink(target, path)` 會以獨占方式建立連結。相對目標是相對於連結父目錄解讀，而非輔助工具根目錄。

`SymlinkDeniedError`、`PathEscapeError` 與 `UnsupportedPathError` 衍生自 `FileHelperError`，用於描述政策失敗。缺少的路徑（包括懸空的讀取／更新目標）、權限、現有的獨占建立目的地、非目錄父節點與作業系統 I/O 失敗，保留原生 Python 例外。不會列印、警告並跳過或結束 CLI。呼叫端負責轉譯為其一般的命令錯誤封裝。

僅支援一般檔案、目錄與明確允許的符號連結。在已建立的根目錄之下，Windows 目錄聯結與其他非符號連結的重解析項目不受支援，且在**兩種**政策模式下都以 `UnsupportedPathError` 拒絕。這包括受含的聯結、葉節點刪除與遞迴刪除：預檢會拒絕它們而不遍歷或移除。`allow_symlinks=True` 不授權聯結的遍歷或刪除。受信任的根目錄別名邊界本身可透過聯結解析，就如同可透過符號連結解析一樣；這不授權該根目錄之下的聯結。讀取／更新循環與過長的連結鏈會明確失敗。遞迴刪除包括整個所選樹；此基礎中沒有排除篩選。未來具排除功能的操作必須只檢查納入的項目，而不是因被排除／無關的連結而拒絕整個專案。

## 安全限制與移轉

POSIX 讀取、獨占檔案建立與文字覆寫，共用同一套父目錄走訪，用於功能檢查、搜尋旗標、不跟隨走訪與描述元清理。葉節點開啟旗標、檔案型別驗證與截斷，仍依操作而異。

讀取會在既有政策下解析支援的受含連結，再開啟已解析的階層，而不跟隨被替換的連結。POSIX 讀取使用與描述元相關的目錄走訪，搭配 `O_DIRECTORY` 與 `O_NOFOLLOW`。目錄描述元在可用時使用 `O_SEARCH` 或 `O_PATH`，讓可搜尋的目錄不需可列舉，包括當 Python 組建使用省略該常數的較舊 SDK 時，使用 Darwin 原生的 `O_SEARCH` 值。每個被取代的父目錄會在其子項開啟後立即關閉。葉節點使用 `O_NOFOLLOW` 與 `O_NONBLOCK`。Windows 讀取會以 `FILE_TRAVERSE` 與 `FILE_READ_ATTRIBUTES` 開啟正規根目錄，再以 `NtCreateFile` 相對於其已驗證的父控制代碼，開啟每個已解析的子項。目錄開啟不要求列舉存取。相對開啟可防止已開啟父目錄上的就地聯結變更，重新導向下一次開啟；僅憑寫入共用限制，無法防止僅屬性重解析更新。每個新控制代碼都會拒絕重解析點，且控制代碼不允許刪除共用。讀取會將已驗證的葉控制代碼複製為獨立擁有的描述元，絕不重新開啟其路徑名稱。
兩種路徑都會在讀取其描述元之前，以 `fstat` 驗證已開啟的檔案，並在成功或失敗時釋放所有控制代碼。Windows 子項開啟的 ABI 結構與指標型別，會在僅限 Windows 的模組中延遲初始化，並透過 Python 的匯入快取重用。如此可避免在較舊的支援 Python 版本中保留型別，且 POSIX 啟動不需要 `ctypes`。控制代碼值與路徑緩衝區維持操作本機。缺少必要安全開啟原語的平台會明確失敗，而不會回退到未檢查的路徑名稱讀取。並行的取代可能導致讀取失敗，或讓讀取繼續讀取已開啟的原始檔案，但無法透過被替換的符號連結重新導向。這不會凍結檔案內容以防就地編輯。

預檢會在遞迴刪除或父目錄建立之前，偵測靜態政策失敗。原子寫入會在取代前重新檢查原始路徑，刪除則會重新檢查每個存取的項目。刪除也會錨定目錄列舉與移除，讓交換已存取父目錄為連結的動作無法重新導向這些操作。系統會避免為每個項目重新開啟絕對根目錄路徑；已建立的根目錄控制代碼絕不會重新繫結到取代項目，即使裝置／inode 值被重用。POSIX 移除會保持附加於已開啟的目錄，即使該目錄被重新命名；驗證會繼續檢查同一棵目錄樹。Windows 會在控制代碼持有期間防止祖先重新命名。並行變更仍可能導致刪除失敗或留下部分結果，預檢不是交易，也不是不可變的樹狀快照。
POSIX 葉節點移除會對錨定父目錄中的目前項目操作；Windows 移除則對其已開啟的葉控制代碼操作。沒有任何操作是通用的無競態沙箱。對於仍使用已驗證路徑的操作（讀取、目錄建立、原子寫入與符號連結建立），可攜式路徑檢查**不是無競態沙箱**：另一個行程可在檢查與系統呼叫之間交換父目錄或項目，變更期間的 I/O 失敗也可能留下部分結果。請另外防範並行的不受信任變更。
獨占檔案建立會如上所述錨定其已解析的父目錄階層。在 POSIX 上，重新命名已開啟的目錄，不會將建立重新導向到其取代項目：建立仍屬於已開啟的目錄，即使它已移出根目錄。這並不保證並行重新命名下命名空間成員關係的穩定性，父目錄錨定也不會讓每個葉節點預檢與隨後的開啟都變成原子操作。
在 Windows 上，獨占建立與文字覆寫在固定父目錄階層後，仍以路徑名稱開啟其葉節點。僅屬性重解析更新可能重新導向這些開啟；它們沒有讀取路徑的父目錄相關控制代碼保護。
輔助工具不會限制子行程或第三方程式碼。

既有的安全寫入機制為此輔助工具提供了參考，但既有共用基礎設施的警告／跳過行為與開發模式連結建立維持不變。請一次移轉一個擁有的操作邊界，在任何早期解析之前，將原始路徑與明確的根目錄／政策帶入輔助工具。連結的命令目錄與開發模式註冊仍屬相依階段。非原子設定寫入保留舊版中繼資料語意。`overwrite_text` 會保持已解析的目錄／檔案物件開啟，但不會在 POSIX 上凍結目錄成員關係：已開啟的目錄或檔案可能被重新命名，操作會繼續對該已開啟的物件進行。受信任根目錄的作業系統祖先仍在輔助工具的政策邊界之外。這不是針對並行命名空間變更或硬連結別名的通用沙箱。缺少必要描述元／控制代碼原語的平台會明確失敗，而不會回退到以路徑為基礎的覆寫。

Windows 路徑分類與目錄模式重解析拒絕具備可攜式迴歸測試。原生 Windows 路徑與聯結測試也存在，在其他主機上會跳過；在 macOS 上執行可攜式案例並不能驗證 Windows 檔案系統系統呼叫或聯結行為。刪除取代測試會在原生主機上，於列舉與移除邊界演練交換；Windows 控制代碼共用行為需要原生 Windows 執行。獨占建立測試涵蓋錨定前與最終開啟時的父目錄取代，以及原生 Windows 父控制代碼固定與可攜式控制代碼生命週期檢查；可攜式檢查不能取代原生 Windows 執行。
