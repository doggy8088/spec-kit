# 發佈工作流程步驟

發佈版本化的 Python 套件，讓工作流程可以重用相同的步驟類型。
自訂步驟使用的型錄與提交合約與工作流程定義不同。

## 準備發行版本

請提供套件，其 `step.type_key` 與 `StepBase.type_key` 相符、版本為加引號且與 PEP 440 相容、附開放原始碼授權與文件。請說明安裝、設定、相依性、輸出、失敗行為、副作用與範例工作流程用法。

請測試有效與無效的設定、回傳的狀態，以及相關的繼續執行與同時執行路徑。請發佈版本化的封存檔，其 `step.yml` 與 `__init__.py` 位於根目錄，或位於恰好一個頂層目錄內。

審查原始碼後，請在可拋棄的已初始化專案中測試已發佈成品的安裝：

```bash
specify workflow step add my-step \
  --from https://github.com/your-org/my-step/releases/download/v1.0.0/my-step-1.0.0.zip
```

安裝會驗證並複製套件，而不會匯入它。也請透過工作流程演練已安裝的類型：載入套件會以你的權限執行 Python。

## 社群提交

請遵循[社群工作流程步驟類型指南](../community/workflow-steps.md)，使用正式的 issue 表單、
版本化封存檔、個別以標籤釘選的檔案 URL、每個檔案的摘要、套件限制，
以及由維護者觸發的中繼資料驗證。

請勿以手動編輯的步驟型錄 PR 取代該 issue 流程。維護者驗證的是中繼資料與發行證據，而非提交的 Python 程式碼。社群步驟型錄仍僅供探索。

## 發行版本更新

當套件內容變更時，請發佈新版本，並使用相同的社群提交 issue 表單進行版本更新與中繼資料修正。
請保留已宣傳的歷史版本。
在取代已安裝的套件之前，請再次審查原始碼；摘要檢查只能識別位元組，
無法判斷這些位元組是否安全。
